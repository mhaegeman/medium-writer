Plan a series on: $ARGUMENTS

1. Read `profile/author.md`, `profile/voice.md`, `profile/interests.yaml`, `ideas.md` and the titles in
   `articles/` and `profile/medium/index.md` so nothing repeats what is already published.
2. Use the `researcher` subagent for a quick landscape check of official documentation, so each
   part rests on real, current capabilities.
3. Design 3–4 parts that each stand alone but build on each other (zero to something working),
   each with: working title, one-sentence takeaway, prerequisites, the code project that threads
   through the series, and which of his real projects could ground it (only those in `author.md`).
4. Write the plan to `series/<series-slug>.md` including a publishing cadence (one per week) and the
   cross-links each part should carry ("previously...", "next...").
5. Append each part to `ideas.md` as `- [ ] [series: <slug> 1/3] Title — angle`.
6. Show the plan and **stop for approval**. Each part is then written with `/article`.
